## 一、项目概述

**项目名称：** SyncPlay  
**项目类型：** 同步播放工具 / 协作工具  
**一句话描述：** 两人异地同步播放视频，进度实时同步，延迟低  
**平台：** Web（浏览器，无需安装）  
**目标环境：** 任意网络环境（局域网 + 跨网段 + 公网，包括对称 NAT / 严格防火墙等不友好场景）

## 〇、v1.0 硬性要求

这是 v1.0 必须满足的**交付标准**，优先级最高：

| # | 要求 | 说明 | v0.3 状态 |
|---|------|------|-----------|
| R0 | **公网环境同步** | 两端用户可以在**任意网络环境**（包括跨运营商、跨 NAT、对称 NAT、企业防火墙等）下成功连接并同步 | ✅ TURN 实现 + 跨网实测主人声明通过 |
| R1 | **一键启动** | 双击 `start.sh` (Mac/Linux) 或 `start.bat` (Windows) 即可运行，无须任何手动配置 | ✅ 已实现,环境缺失自动装。**v0.3 后**改双击 .dmg / .exe |
| R2 | **启动后界面中配置房间** | 所有房间配置（创建/加入、房间号输入）都在 Web UI 中完成，不依赖命令行 | ✅ |
| R3 | **双方均能选择创建或加入** | 任何一方都可以点"创建房间"或"加入房间"，不受角色限制 | ✅ |
| R4 | **加入后自动构建同步链路** | 加入房间成功后自动建立 WebRTC P2P / TURN 中继连接，双方加载视频即同步 | ✅ TURN 路径验证通过 |

### v1.0 场景剧本

```
场景：异地异地两位好友一起看片
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. A 在 Mac 上双击 start.command
   - 服务自动起，浏览器自动开 http://localhost:8080/client/
   - A 选本地视频，点"创建房间"
   - 获得房间号如 "room-abc123"

2. A 把房间号发给 B（微信/QQ/手输）

3. B 在 Windows 上双击 start.bat
   - 服务自动起，浏览器自动开 http://localhost:8080/client/
   - B 选同一个视频，点"加入房间"，输入 room-abc123

4. 双方显示"已连接" → 自动同步
   - A 播放/暂停/seek → B 同步跟随
   - 双方看到一致的播放位置
```

## 二、核心功能需求

### 2.1 同步播放（核心）

| 需求描述 | 技术关键点 |
|----------|-----------|
| 两人播放同一视频时进度一致 | 进度同步协议 |
| 一方快进，另一方自动跳转 | seek 指令传递 |
| 一方暂停/播放，另一方同步 | play/pause 指令传递 |
| 同步延迟尽可能低 | WebRTC / 低延迟传输 |

---

## 三、系统架构

```
用户 A                   用户 B
  ↓                         ↓
本地视频文件 ←→ 浏览器 ←→ WebRTC DataChannel ←→ 浏览器 ←→ 本地视频文件
  ↓                         ↓
      ←←←←←←←← 信令服务器（仅建立连接）←←←←←←←←
```

**两条通道：**
1. **指令通道** — 传递 pause / seek / play 命令（WebRTC DataChannel）
2. **视频流** — 各自本地播放，视频文件不经过服务器

**注意：** MVP 阶段视频文件不走服务器，各自在本地播放。服务器只传指令。

## 四、技术选型

| 模块 | 技术选型 |
|------|----------|
| 平台 | Web（浏览器，无需安装） |
| 视频播放 | HTML5 `<video>` 标签 |
| P2P 库 | PeerJS（封装 WebRTC，内置 STUN/TURN） |
| 信令服务 | PeerJS 官方公共服务器（测试）/ 自建 Node.js（生产） |
| 前端框架 | 纯 HTML + JS（最轻量） |

### 功能范围

| 功能 | 说明 | 对应 v1.0 要求 |
|------|------|---------------|
| ✅ 视频选择 | 两端用户各自选择本地视频文件 |  |
| ✅ 播放/暂停同步 | 一方播放/暂停，另一方同步跟随 |  |

---

### 排除范围（暂不做）
- ❌ 视频流媒体传输（两端都播本地文件，不涉及网络传输视频）
- ❌ 用户列表、聊天等社交功能
- ❌ 用户注册、登录、密码、邮箱、手机号
- ❌ 房间密码/链接有效期/角色权限

---

### 同步原理

1. A 点击播放 → 发送 `{"type": "play", "position": 12.5}` 到 B
2. B 收到 → 立即将 video.currentTime 设为 12.5 并播放
3. A 拖动进度条 → 发送 `{"type": "seek", "position": 45.0}` 到 B
4. B 收到 → 立即将 video.currentTime 设为 45.0

**延迟目标：** < 200ms
