# SyncPlay 项目需求文档

> 视频同步播放工具 — 项目正式启动

---

## 一、项目概述

**项目名称：** SyncPlay  
**项目类型：** 同步播放工具 / 协作工具  
**一句话描述：** 两人异地同步播放视频，进度实时同步，延迟低  
**平台：** Web（浏览器，无需安装）

---

## 二、核心功能需求

### 2.1 同步播放（核心）

| 需求描述 | 技术关键点 |
|----------|-----------|
| 两人播放同一视频时进度一致 | 进度同步协议 |
| 一方快进，另一方自动跳转 | seek 指令传递 |
| 一方暂停/播放，另一方同步 | play/pause 指令传递 |
| 同步延迟尽可能低 | WebRTC / 低延迟传输 |

---

## 三、系统架构

```
用户 A                   用户 B
  ↓                         ↓
本地视频文件 ←→ 浏览器 ←→ WebRTC DataChannel ←→ 浏览器 ←→ 本地视频文件
  ↓                         ↓
      ←←←←←←←← 信令服务器（仅建立连接）←←←←←←←←
```

**两条通道：**
1. **指令通道** — 传递 pause / seek / play 命令（WebRTC DataChannel）
2. **视频流** — 各自本地播放，视频文件不经过服务器

**注意：** MVP 阶段视频文件不走服务器，各自在本地播放。服务器只传指令。

---

## 四、技术选型

| 模块 | 技术选型 |
|------|----------|
| 平台 | Web（浏览器，无需安装） |
| 视频播放 | HTML5 `<video>` 标签 |
| P2P 库 | PeerJS（封装 WebRTC，内置 STUN/TURN） |
| 信令服务 | PeerJS 官方公共服务器（测试）/ 自建 Node.js（生产） |
| 前端框架 | 纯 HTML + JS（最轻量） |

---

## 五、MVP 定义

### 目标
**极简 MVP — 只做进度同步**

---

### 功能范围

| 功能 | 说明 |
|------|------|
| ✅ 视频选择 | 两端用户各自选择本地视频文件 |
| ✅ 播放/暂停同步 | 一方播放/暂停，另一方同步跟随 |
| ✅ 进度同步 | 一方 seek（拖进度条），另一方同步跳转 |
| ✅ 连接建立 | 两人通过房间号/链接加入同一会话 |

---

### 排除范围（暂不做）
- ❌ 视频流媒体传输（两端都播本地文件，不涉及网络传输视频）
- ❌ 用户列表、聊天等社交功能
- ❌ 用户认证、注册

---

### 同步原理

1. A 点击播放 → 发送 `{"type": "play", "position": 12.5}` 到 B
2. B 收到 → 立即将 video.currentTime 设为 12.5 并播放
3. A 拖动进度条 → 发送 `{"type": "seek", "position": 45.0}` 到 B
4. B 收到 → 立即将 video.currentTime 设为 45.0

**延迟目标：** < 200ms

## 六、开发阶段

#### Phase 1 — MVP（当前）
- 纯 Web 版本
- 两人本地视频同步播放
- 手动选择视频文件
- 房间号连接

#### Phase 2（后续）
- 降低同步延迟
- UI 优化

#### Phase 3（后续）
- 支持流媒体拉流
- 本地播放 + 远程拉流
