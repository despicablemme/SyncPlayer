## 🎯 v1.0 架构决策（2026-06-06 明确）

**v1.0 核心要求**（来自 REQUIREMENTS.md）：
- 公网环境（任何网络）可同步
- 实现方式不限

### 三候选方案

| 方案 | 说明 | 改动量 | 推荐 |
|------|------|--------|------|
| **A. TURN 中继** | 保留 WebRTC，加 ICE servers 走 TURN | 🟢 小 | ⭐ 首选 |
| B. 第三方 WebRTC 平台 | 接入 LiveKit / Daily SDK | 🔴 大 | 备选 |
| C. 纯 WebSocket 转发 | 不调 WebRTC，服务端转发指令 | 🟡 中 | 备选 |

### ✅ 选定方案 A：TURN 中继（推荐）

**原理**：在 PeerJS 客户端配置中加 TURN 服务器地址，~15% 穿透失败场景走 TURN 中继。

**架构变动**（最小）：
```
原架构（v0.2）：
  浏览器 PeerJS ─► 公共/自建信令服务器 ─► 浏览器 PeerJS
                （直连 ~85% 成功）

v1.0 架构（加 TURN）：
  浏览器 PeerJS ─► 公网信令服务器 ─► 浏览器 PeerJS
       │                                  │
       └──► 必要时走 TURN 中继 ◄───────────┘
            （Metered / coturn，免费额度够）
```

**实现点**：
1. `src/client/app.js` 的 `CONFIG.ICE_SERVERS` 填入 TURN 凭据
2. 信令服务器部署到公网（Cloudflare Tunnel / VPS）
3. 客户端默认连自建信令（不再走 PeerJS 公共）

**优点**：
- 视频永远不上服务器（隐私最好）
- 现有 28 个单元测试不受影响
- 改动集中在配置

### 备选方案 B / C 概要

- **B (LiveKit/Daily)**：适合需要快速跑通、不在乎技术债的项目
- **C (纯 WebSocket)**：适合未来扩展多人/需要服务端逻辑的场景

## 总体架构

```
┌─────────────┐                              ┌─────────────┐
│   用户 A     │                              │   用户 B     │
│  (浏览器)    │                              │  (浏览器)    │
│             │                              │             │
│  本地视频   │                              │  本地视频   │
│      ↕      │                              │      ↕      │
│  HTML5 <video>                              │  HTML5 <video>
│      ↕      │                              │      ↕      │
│  SyncEngine │◄──────► WebRTC DataChannel ◄►│  SyncEngine │
│      ↕      │      (play/pause/seek/...)   │      ↕      │
│  PeerJS     │                              │  PeerJS     │
│   Client    │                              │   Client    │
└──────┬──────┘                              └──────┬──────┘
       │                                            │
       │   信令（仅建立 P2P 连接，不传视频）         │
       │                                            │
       └──────────────┬─────────────────────────────┘
                      ▼
            ┌─────────────────────┐
            │  PeerJS 信令服务器   │
            │  (公共或自建)        │
            └─────────────────────┘
```

**关键原则**：
- 视频文件**永远不上传**
- 同步指令**只走 P2P**（不经过服务器）
- 信令服务器**只负责建立连接**

## 同步引擎核心（`client/app.js`）

### 状态机

```
                    ┌──────────────┐
   本地点击 ─────►  │              │  ──►  send(msg)
                    │   SyncEngine │
   远端消息 ─────►  │              │  ──►  video.currentTime / play / pause
                    └──────────────┘
                           │
                  guardUntil 时间戳
                  （屏蔽 200ms 内本地事件）
```

**关键设计**：
- 用 `guardUntil` 时间戳**标记屏蔽窗口**（替代 v1 的 50ms 定时器）
- 仅当**位置偏差 > 0.3s** 时才校正（避免微小抖动）
- 心跳 5s 一次，漂移检查 10s 一次

### 漂移校准

```
A 端                                         B 端
  │                                            │
  │  drift_check { remotePosition: 12.5 }       │
  ├──────────────────────────────────────────►  │
  │                                            │
  │  drift_response { myPosition: 12.7, ... }  │
  │  ◄──────────────────────────────────────────┤
  │                                            │
  │  A 计算 delta = 12.5 - 12.7 = -0.2        │
  │  abs(0.2) < 0.5 → 不校正                  │
```

## 重连机制

```
连接断开
    │
    ▼
remoteStatus 变为 "已断开"
    │
    ▼
attempts = 1
    │ 延迟 2s
    ▼
attempts = 2
    │ 延迟 4s
    ▼
...
    │
    ▼
attempts = 5 (放弃)
    │
    ▼
toast 提示"重连失败，请重新加入"
```

**指数退避**：2s → 4s → 6s → 8s → 10s

## 信令服务器（`server/server.js`）

基于 [PeerJS 官方 Server](https://github.com/peers/peerjs-server) 库：

- 默认端口 9000，路径 `/`
- WebSocket 信令
- 监控连接/断开事件
- 支持优雅退出

**自建好处**：
- 不依赖 PeerJS 公共服务器（可能限流/挂掉）
- 可以加鉴权/限流
- 自己掌控日志
