# v0.6 Runbook — 主 agent 具体怎么跑

> **这是什么？** 主人定下 v0.6 目标后, 主 agent (Jarvis) **具体要做什么**的逐步操作手册。
> **何时使用？** 主人说"v0.6 目标 = X" 之后, 主 agent **第一件事**就是读本文件, 然后照着跑。
> **最后更新：** 2026-06-09

---

## 🚦 一句话

**主 agent 不写代码、不跑测试**——主 agent 做 4 件事：① 拆任务写文档 ② 派 subagent 监督 Claude Code ③ 验收 ④ 写 CHANGELOG/STATUS/AGENT_PRACTICES + push。

---

## 📊 完整流程图（按时间顺序）

```
[0] 主人说 "v0.6 目标 = X"
         ↓
[1] 主 agent: 复述理解 + 跟主人确认 (per MEMORY #13/#14)
         ↓
[2] 主 agent: 拆 v0.6 → N 个 Builder 任务 (每任务对应一个 sub-task)
         ↓
[3] 主 agent: 写文档 (3 文件 × N 任务)
         - tasks/v0.6.0-X-builder.md  (用 templates/builder-task.md 模板)
         - tasks/v0.6.0-X-context.md  (用 templates/context-summary.md 模板)
         - tasks/v0.6.0-X-tester.md   (用 templates/tester-task.md 模板)
         ↓
[4] 主 agent: commit + push 任务书到 syncplay
         ↓
[5] 主 agent: 派 subagent 1 (Builder orchestrator) — **等完工事件**
         ↓ subagent 1 跑 claude --add-dir ... -p "<builder 任务书>"
         ↓ Claude Code 写代码 + 跑 unit test + commit
         ↓ subagent 1 抓 BUILDER_DONE 标记, 验证 commit, 报告主 agent
[6] 主 agent: 立刻查交付 (per MEMORY #20 铁律) + 跟主人汇报
         ↓
[7] 主 agent: 派 subagent 2 (Tester orchestrator) — **等完工事件** (SERIAL, 不并行)
         ↓ subagent 2 跑 claude --add-dir ... -p "<tester 任务书>"
         ↓ Claude Code 跑验证 + 写报告 tasks/v0.6.0-X-test-report.md
         ↓ subagent 2 抓 TESTER_DONE 标记, 验证报告, 报告主 agent
[8] 主 agent: 验收 (Reviewer 角色)
         - 读 Builder commit diff
         - 读 Tester 报告
         - 按 acceptance.md 验收清单逐项核对
         ↓
[9] 主 agent: 给决策 → PASS / NEED FIX / FAIL
         - PASS  → 写 CHANGELOG + 更新 STATUS + 写 AGENT_PRACTICES (如有) + commit + push + 汇报
         - NEED FIX → 写新 Builder 任务书 (带 Tester 报告) → 回到 [5]
         - FAIL → 写 AGENT_PRACTICES 记录 → 跟主人汇报 → 等主人拍
         ↓
[10] 重复 [5]-[9] 直到 v0.6 全部子任务 PASS
         ↓
[11] 主 agent: v0.6 完工汇报主人 + 更新 STATUS/ROADMAP
```

## 🎯 主 agent 在每个阶段具体做什么

### [0] 主人发布目标

**主 agent 做**:
- 接收主人的 v0.6 目标描述

**不做**:
- ❌ 立刻派活（要等阶段 1 跟主人确认）

---

### [1] 复述理解 + 跟主人确认

**主 agent 做**:
- **复述**主人的目标（一句话总结 + 关键决策点）
- 列**未明确**的细节（如有），问主人
- 等主人**确认**才进 [2]

**不做**:
- ❌ 凭印象开始拆任务
- ❌ 假设主人没说的细节

**耗时**：2-5 分钟

---

### [2] 拆任务 → N 个 Builder 子任务

**主 agent 做**:
- 把 v0.6 大目标拆成 **N 个原子子任务**
  - 每个子任务 = 1 个 git commit
  - 每个子任务 = 1 个文件 / 1 个明确功能 / 1 次 commit
  - 太大 → 拆小
  - 太小 → 合并
- 给每个子任务一个 ID: `v0.6.0-<milestone>-<sub-id>`
  - 例: `v0.6.0-macos-install-doc-1`, `v0.6.0-macos-install-doc-2`

**典型 v0.6 拆法**（以 macOS 安装文档为例）:
- 子任务 1: 写 `docs/INSTALL_macOS.md` 主文档
- 子任务 2: 加 SHA256 校验说明
- 子任务 3: 加截图（quarantine 处理前后）
- 子任务 4: 更新 README 链接到新文档
- 子任务 5: 写 CHANGELOG 条目（实际是 [9] 阶段，但可以提前计划）

**不做**:
- ❌ 把整个 v0.6 塞一个 Builder 任务
- ❌ 把 v0.6 拆成 20 个微任务（太碎）

**耗时**：5-10 分钟

---

### [3] 写文档 (3 文件 × N 任务)

**主 agent 做**:
对每个子任务, 写 3 个文件:

| 文件 | 用什么模板 | 写什么 |
|---|---|---|
| `tasks/v0.6.0-X-builder.md` | `templates/builder-task.md` | 目标/必读 context/详细要求/禁区/验收标准/完成后动作 |
| `tasks/v0.6.0-X-context.md` | `templates/context-summary.md` | AGENT_PRACTICES 关键摘要(2-5条)/STATUS 摘要/相关路径速查 |
| `tasks/v0.6.0-X-tester.md` | `templates/tester-task.md` | 验证清单/必跑项目/报告输出位置 |

**关键约束**:
- 必读 context **必须**绝对路径 (`/Users/bruce/...`)
- 任务书**必须**含"自我验证"段（per AGENT_PRACTICES #16）
- 任务书**明确**列禁区 (`docs/STATUS.md` 等) — Builder 改了就 NEED FIX

**不做**:
- ❌ 漏写 context 摘要（Builder 不知道关键教训）
- ❌ 漏写 Tester 任务书（独立 context 硬约束破）

**耗时**：每个子任务 5-10 分钟，3 个任务 = 15-30 分钟

---

### [4] commit + push 任务书

**主 agent 做**:
```bash
cd ~/CodeProjects/syncplay
git add tasks/ docs/  # 如果改了 docs/
git commit -m "tasks(v0.6.0): add task books for <milestone>"
git push origin main
# 验证 (per AGENT_PRACTICES #15)
git fetch origin main
git rev-parse main origin/main  # 必须一致
```

**不做**:
- ❌ 跳过 push（subagent 拿不到任务书）
- ❌ 跳过 fetch 验证（#15 教训：SSL 错可能假阳性也可能真失败）

**耗时**：1-2 分钟

---

### [5] 派 subagent 1 (Builder orchestrator)

**主 agent 做**:
```typescript
// 主 agent (Jarvis) 在 OpenClaw 派活
const builderTask = `
你是 Builder orchestrator, 跑 Claude Code 完成 Builder 任务.

步骤:
1. 验证环境:
   - claude --version
   - echo "\${ANTHROPIC_AUTH_TOKEN:***"  # 验证 key 在 env (per #11)
2. 读任务书:
   - cat /Users/bruce/CodeProjects/syncplay/tasks/v0.6.0-X-builder.md
   - cat /Users/bruce/CodeProjects/syncplay/tasks/v0.6.0-X-context.md
3. 跑 Claude Code (per AGENT_PRACTICES #16 必加 --add-dir):
   cd /Users/bruce/CodeProjects/syncplay
   claude --add-dir /Users/bruce/CodeProjects/syncplay \\
          -p "\$(cat tasks/v0.6.0-X-builder.md tasks/v0.6.0-X-context.md)"
4. 监督输出: 抓 BUILDER_DONE: <commit-sha> 标记
5. 验证 commit:
   cd /Users/bruce/CodeProjects/syncplay
   git log -1 --format="%H %s"
   git show --stat HEAD
6. 报告: commit-sha / 改了什么 / unit test 结果 / 任何警告

红线:
- ❌ 不让 Claude Code 改 docs/CHANGELOG.md / docs/STATUS.md / AGENT_PRACTICES.md
- ❌ 不让 Claude Code git push
- ❌ 不在 prompt 里贴 ANTHROPIC_AUTH_TOKEN
- ❌ 失败超过 1 次就报告, 不重试
- ✅ 跑完立刻 push 完工事件给 Jarvis (per MEMORY #20)
`;

await sessions_spawn({
  task: builderTask,
  taskName: "builder-v0.6.0-X",
  runtime: "subagent",
  mode: "run"
});
await sessions_yield();  // 等完工事件
```

**不做**:
- ❌ 不让 Builder 和 Tester 并行（per control-claude.md "fresh context 硬约束"）
- ❌ 不在 prompt 里贴凭证
- ❌ 不用 `claude -p` (缺 --add-dir, 读不到 syncplay)

**耗时**：5-30 分钟（看子任务复杂度）

---

### [6] 立刻查交付 + 汇报主人

**主 agent 做**:
- 收到 subagent 1 完工事件
- 立刻查 subagent 1 报告（commit-sha + 改了哪些文件 + unit test 结果）
- 跟主人汇报（per reporting.md 标准格式）：
  ```
  ## Builder 完工 (v0.6.0 子任务 X)
  
  ### ✅ commit `<sha>`
  <commit message>
  
  ### 关键内容
  - 改了 <file1>, <file2>, ... (N 行)
  - unit test: N passed
  
  ### 下一步
  派 Tester 跑 (独立 context) — 等完工事件
  ```

**不做**:
- ❌ 静默等主人问（per MEMORY #20 铁律）

**耗时**：1-2 分钟

---

### [7] 派 subagent 2 (Tester orchestrator)

**主 agent 做**:
```typescript
// ⚠️ 必须在 subagent 1 完工事件后, 才能派 (per control-claude.md)
const testerTask = `
你是 Tester orchestrator, 跑 Claude Code 完成 Tester 任务 (fresh context).

⚠️ 关键: Fresh context
- Builder subagent 1 已退出 (context 销毁)
- 你的进程是新的
- claude -p 启动的 Claude Code 是新 session
- **绝对不能**让 Claude Code 读 Builder 的 conversation / Builder 的笔记

步骤:
1. 验证环境: (跟 Builder 一样)
2. 读任务书:
   - cat /Users/bruce/CodeProjects/syncplay/tasks/v0.6.0-X-tester.md
3. 跑 Claude Code (per AGENT_PRACTICES #16 必加 --add-dir):
   cd /Users/bruce/CodeProjects/syncplay
   claude --add-dir /Users/bruce/CodeProjects/syncplay \\
          -p "\$(cat tasks/v0.6.0-X-tester.md)"
   ⚠️ 注意: 这里**只**注入 tester 任务书, 不注入 builder 任务书 / builder context
4. 监督输出: 抓 TESTER_DONE: <path> 标记
5. 验证报告: cat tasks/v0.6.0-X-test-report.md
6. 报告: 报告路径 / PASS/FAIL / 关键发现

红线:
- ❌ 不让 Claude Code 改任何源代码
- ❌ 不让 Claude Code 改 docs/ 文档
- ❌ 不让 Claude Code git push
- ❌ 注入 builder 任务书 / builder context (破坏 fresh context)
- ❌ 重试超过 1 次
- ✅ 跑完立刻 push 完工事件给 Jarvis
`;

await sessions_spawn({
  task: testerTask,
  taskName: "tester-v0.6.0-X",
  runtime: "subagent",
  mode: "run"
});
await sessions_yield();  // 等完工事件
```

**不做**:
- ❌ 让 Tester 看 Builder 的 conversation（破坏 fresh context）
- ❌ 让 Tester 改源代码（Tester 只测不修）

**耗时**：5-20 分钟（看测试复杂度）

---

### [8] 验收 (Reviewer 角色)

**主 agent 做**:
- 读 Builder commit: `git -C ~/CodeProjects/syncplay show HEAD`
- 读 Tester 报告: `cat tasks/v0.6.0-X-test-report.md`
- 按 `acceptance.md` 验收清单**逐项核对**:
  - [ ] Builder commit 存在, message 规范
  - [ ] Builder 没改禁区 (docs/STATUS.md 等)
  - [ ] unit test 跑通
  - [ ] Tester 报告每项验证有 PASS/FAIL + 证据
  - [ ] 任务书每个验收标准都达成
  - [ ] 没超范围改动
  - [ ] commit 不超 500 行（除非明确）

**不做**:
- ❌ 跳过 Tester 报告直接验收
- ❌ 凭印象给 PASS

**耗时**：5-10 分钟

---

### [9] 给决策 + 后续动作

#### ✅ PASS 路径

**主 agent 做**:
```bash
cd ~/CodeProjects/syncplay
# 1. 写 CHANGELOG.md (主 agent 专属)
# 2. 更新 docs/STATUS.md
# 3. 写 AGENT_PRACTICES.md (如有新教训)
git add docs/CHANGELOG.md docs/STATUS.md AGENT_PRACTICES.md
git commit -m "docs(v0.6.0): release notes for <milestone>"
git push origin main
# 4. 验证 (per #15)
git fetch origin main
git rev-parse main origin/main
```

**汇报主人**（per reporting.md）:
```
## v0.6.0 子任务 X 验收

### ✅ PASS
- Builder: <sha>
- Tester: <report path> (PASS, 6/6 项)
- 任务书验收: 5/5 达成

### 后续动作
- ✅ CHANGELOG.md 已加
- ✅ STATUS.md 已更新
- ✅ git push 完成 (commit <sha>)

### 新教训
无 / #17: <一句话>

### 下一任务
v0.6.0 子任务 Y — 等主人拍 / 我自动派
```

**不做**:
- ❌ 跳过 CHANGELOG（让 Claude Code 改 = NEED FIX）

#### ⚠️ NEED FIX 路径

**主 agent 做**:
- 写新 Builder 任务书: `tasks/v0.6.0-X-fix1.md`
  - **必须**包含 Tester 报告作为 context
  - **明确**修复指令: "改 X 文件 Y 函数, 从 A 改成 B"
- 派新 Builder subagent (回到 [5])

#### ❌ FAIL 路径

**主 agent 做**:
- 写 AGENT_PRACTICES.md (新教训)
- 跟主人汇报: 任务失败 + 原因 + 我的建议
- 等主人决策: 重新拆任务 / 换方向 / 取消

**耗时**：5-10 分钟

---

### [10] 重复 [5]-[9] 直到 v0.6 全部子任务 PASS

**主 agent 做**:
- 一个子任务 PASS 后, 派下一个
- 每个子任务独立 commit + 独立验收
- **不**一次性派多个子任务（避免一个失败拖累其他）

**不做**:
- ❌ 一次性派 3 个 Builder subagent 并行（per control-claude.md）

---

### [11] v0.6 完工汇报

**主 agent 做**:
- 跟主人汇报: v0.6 全部子任务 PASS, 总结
- 更新 docs/STATUS.md (v0.6 → ✅ Shipped)
- 更新 docs/ROADMAP.md (v0.7 → 下一目标)
- 写 CHANGELOG.md (v0.6.0 release 条目)
- commit + push + 验证

**耗时**：10-15 分钟

| **总计** | **30-80 分钟/子任务** | **80-400 分钟 (1.3-6.5 小时)** |

## 🚨 主 agent 红线（必避）

| 红线 | 说明 |
|---|---|
| ❌ 写代码 | Builder 的活, 主 agent 写 = 越权 |

| ❌ 主人没确认就派活 | 拆完任务**必须**先跟主人确认 |
