## 给 Reviewer (主 agent) 的备注

1. **未做浏览器 e2e**: 任务书验证项以状态机逻辑 + 匹配算法 + 集成点为重, 单测已覆盖所有边角. 沙盒无 PeerJS 信令可达, 完整 e2e (两窗口连真实 WebRTC) 需主人将来在有公网 + 双机器的环境复核. 单测 + Node REPL smoke + 静态代码审查构成完整的"逻辑正确性"证明, 浏览器层只缺 peerjs.connect 那条路.
2. **任务书与实际单测数量对账**: 任务书"60 新"对账: 60 = 28 (room-state) + 32 (video-match). 任务书写的是 32 + 28, 实际是 28 + 32, 顺序相反, **数字都对, 报告用了实际值**.
3. **videosMatch 的"不 fallback"语义**: 见 video-match.js 测试 "短链 / 重定向场景" — 两端 URL 不同时, 即使 fileName / duration 都匹配, 也**不**返回 true. 任务书 REQUIREMENTS.md 注释也写了这个限制. 单测 `test/unit/video-match.test.js:115-120` 验证. **Builder 选择严格顺序而非 OR-fallback, 是合理决策** (避免"对端用不同 URL 看同一个 YouTube 视频"被误判匹配). 如果将来需要支持短链/重定向, 应改算法为 (URL match || (fileName match AND duration match)), 单独提一个任务.
4. **状态机对子任务 A 的扩展**: A 加了 `disconnected` 中间态? 没, A 没加新状态, A 只在 exitRoom() 切回 no_room. C 改后状态机 6 态, A 改前 4 态 (`no_room / connecting / in_room / disconnected`). C 删了 `in_room` 和 `disconnected` (合并到 6 态的 in_room_* 子状态). **这是预期的**, 因为 C 接管了状态机, 在 A 基础上重构. A 的 exitRoom() 仍工作 (切 no_room).
5. **`conn.on('open')` 不再无条件 `engine.start()`**: Builder 在 commit message 和代码注释都标了 — 改成"只有进 in_room_synced 才启动", 同步指令 gating 由 roomState 的 listener 控制. **正确**: 没视频 / 一方没视频 / 不匹配时不同步, 节省带宽 + 避免无意义心跳.
6. **`video_info` 消息不进 SyncEngine**: `conn.on('data')` 过滤 `type === 'video_info'` 走 `onPeerVideoInfo` (app.js:184-187), 不进 engine.handle. **正确**: engine 不认识这个 type, 早返回避免 SyncEngine 误处理.
7. **测试产物清理**: 测试期间未创建任何临时文件, 未启动任何后台服务. `git status` 干净, 只新增 `tasks/v0.6.0-video-decouple-test-report.md`.
