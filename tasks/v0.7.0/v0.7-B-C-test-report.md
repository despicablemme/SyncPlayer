## §1 MSE 实现 (5 态状态机 + 队列 + cleanup)

### `desktop/src/client/mse-player.js` (新建, 195 行)

**Class `MsePlayer`**:

| 字段 | 类型 | 说明 |
|------|------|------|
| `video` | HTMLVideoElement | constructor 必传, 否则抛 `MSE_NO_VIDEO_ELEMENT` |
| `mediaSource` | MediaSource \| null | 由 `_createMediaSource()` 创建, 触发 `sourceopen` 后 resolve |
| `sourceBuffer` | SourceBuffer \| null | `addSourceBuffer(mimeType, codec)` 后创建 |
| `state` | `'idle'\|'open'\|'ended'\|'error'` | 状态机 |
| `queue` | Array<Function> | `appendFmp4` 在 `sourceBuffer.updating=true` 时的待执行任务队列 |
| `_destroyed` | boolean | 防止 destroy 后再 append / addSourceBuffer 的护盾 |

**关键方法行为**:

| 方法 | 行为 |
|------|------|
| `_createMediaSource()` | `new MediaSource()` → `URL.createObjectURL(ms)` → `video.src = url` → 监听 `sourceopen` resolve |
| `_ensureMediaSource()` | 幂等, 多次调用只创建一次 |
| `addSourceBuffer(mimeType, codec)` | await `_ensureMediaSource()` → `mediaSource.addSourceBuffer(\`${mimeType};codecs="${codec}"\`)` → 监听 `updateend` + `error` |
| `appendFmp4(bytes)` | 若 `updating=true` 入队; 否则直接 `_doAppend(bytes)` |
| `_doAppend(bytes)` | 注册一次性 `updateend`/`error` listener, 调用 `appendBuffer`, 出错时 `try/catch` 兜回 |
| `_drain()` | `updateend` 时触发, 从 queue 取出下一个任务执行 |
| `end()` | await 当前 update 完成 → `mediaSource.endOfStream()` → state='ended' |
| `destroy()` | **顺序很关键**: 1) `sourceBuffer.abort()` (if updating) → 2) `sourceBuffer = null` → 3) `mediaSource.endOfStream()` (if open) → 4) `URL.revokeObjectURL(video.src)` → 5) `video.removeAttribute('src')` + `video.load()`. 幂等 (第二次调用 no-op). |

**Browser-side 暴露**:
```js
if (typeof window !== 'undefined') {
  window.SyncPlayMedia = window.SyncPlayMedia || {};
  window.SyncPlayMedia.MsePlayer = MsePlayer;
}
```

### `desktop/src/shared/mp4-ftyp-parser.js` (新建, 102 行)

**`parseFtyp(bytes) -> { mimeType, codec, majorBrand, isFragmented }`**

**Audit 诚实声明** (per MEMORY #47 + #14 求证):
- ftyp box 只含**品牌标识符** (4 ASCII chars each, e.g. 'avc1', 'hvc1', 'isom')
- 完整 profile/level 字符串 (e.g. 'avc1.640028' = H.264 High@4.0) 在 avcC / hvcC 配置 box 里
- 本任务只解析品牌, 返回 4CC hint ('avc1', 'hvc1' 等)
- 现代 Chromium MSE 接受 4CC hint 作为 codec= 参数, **从流的 codec config box 读真实 profile**
- B-D+ 范围如要 'avc1.640028' 全字符串, 需要走 moov box + 解析 avcC atom

**品牌映射表**:
```js
const VIDEO_BRAND_HINTS = {
  avc1: 'avc1',  avc3: 'avc1',   // H.264
  hvc1: 'hvc1',  hev1: 'hev1', hevc: 'hvc1',  // HEVC
  av01: 'av01',                      // AV1
  vp09: 'vp09', vp9: 'vp09',        // VP9
  vp08: 'vp08',                      // VP8
};
```

**Fallback**: 未识别品牌 → 返回 `'avc1'` (H.264 是 ffmpeg.wasm copy 路径最常见输出, MSE 可从流 codec box 自行探测)

**Browser-side 暴露**:
```js
if (typeof window !== 'undefined') {
  window.SyncPlayMedia = window.SyncPlayMedia || {};
  window.SyncPlayMedia.parseFtyp = parseFtyp;
}
```

## §2 `loadVideo()` mkv/avi/flv 分支集成

### `desktop/src/client/app.js` 变更 (diff 概要)

**变更前** (4 行):
```js
function loadVideo(src, label) {
  fileName.textContent = label;
  video.src = src;
  video.style.display = 'block';
  noVideo.style.display = 'none';
  video.load();
}
```

**变更后** (async + 容器分支, ~70 行):
```js
let activeMse = null;  // 跟踪 active MsePlayer, 二次加载不泄漏

const { MsePlayer, transmuxToFmp4, parseFtyp } = window.SyncPlayMedia || {};
const CONTAINER_RE = /\.(mkv|avi|flv|mov|wmv)(\?|$)/i;

async function loadVideo(src, label, options = {}) {
  // 1. 销毁前一个 MsePlayer (幂等)
  if (activeMse) { try { activeMse.destroy(); } catch {} activeMse = null; }

  // 2. 检测容器文件 (本地 File.name 或 远程 URL 末尾)
  const containerName = (options.file && options.file.name) || src || '';
  const isContainer = !src.startsWith('data:') && CONTAINER_RE.test(containerName);

  // 3. 容器文件走 transmux + MSE 路径
  if (isContainer && MsePlayer && transmuxToFmp4 && parseFtyp) {
    try {
      toast('正在转封装 mkv/avi/flv ...', 'info');
      const input = options.file || await fetch(src).then(r => r.blob());
      const fmp4Bytes = await transmuxToFmp4(input, {
        onProgress: ({ percent }) => toast(`转封装进度 ${percent.toFixed(0)}%`, 'info'),
      });

      let ftypInfo;
      try { ftypInfo = parseFtyp(fmp4Bytes); }
      catch { ftypInfo = { mimeType: 'video/mp4', codec: 'avc1' }; } // fallback

      const mse = new MsePlayer(video);
      activeMse = mse;
      await mse.addSourceBuffer(ftypInfo.mimeType, ftypInfo.codec);
      await mse.appendFmp4(fmp4Bytes);
      await mse.end();

      // loadedmetadata / canplay / timeupdate 由 video element 自动触发,
      // SyncEngine.bindVideoEvents 不需要改
      return;
    } catch (e) {
      const msg = (e && e.message) || String(e);
      if (msg.includes('SOFT_ENCODE_FALLBACK_UNSUPPORTED')) {
        toast('SyncPlay 暂不支持此格式, 请用 VLC 打开或转码为 MP4 (H.264+AAC)', 'error');
        return;
      }
      console.error('[loadVideo] transmux error', e);
      toast(`加载失败: ${msg}`, 'error');
      return;
    }
  }

  // 4. 默认路径 (mp4 / webm / m3u8 / blob) 不变
  video.src = src;
  video.load();
}
```

**调用方同步更新**:
- `videoInput.change`: `loadVideo(url, '本地: ' + file.name, { file })` (传 file 给 loadVideo 跳过 fetch, 直接 transmux)
- `loadUrlBtn.click`: 不变 (URL 走 fetch 路径)

**未破坏**:
- 现有 `mp4/webm/m3u8/blob` 路径走 `video.src = src; video.load()` (line 4 的默认分支)
- `loadedmetadata` / `error` 事件监听器 (line 268-278) 不动 — MSE pipeline 完成后 `<video>` 自动触发 loadedmetadata
- `SyncEngine.bindVideoEvents` / `ConnectionManager` / sync 协议**零修改**
