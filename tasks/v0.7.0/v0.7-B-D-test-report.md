## §1 hls.js 实现

新增 `desktop/src/client/hls-player.js`，入口 class 为 `HlsPlayer`：

- 构造时无 video element 抛出 `HLS_NO_VIDEO_ELEMENT`，初始状态为 `idle`。
- Safari 原生 HLS 优先：检查 `application/vnd.apple.mpegurl` 和 `application/x-mpegURL`，可用时直接设置 `video.src`，不创建 hls.js 实例。
- fallback 路径检查 `Hls.isSupported()`，以 `{ enableWorker: true, lowLatencyMode: false }` 创建 hls.js。
- 调用 `loadSource(url)` + `attachMedia(video)`，状态转为 `loading`；收到 `MANIFEST_PARSED` 后转为 `playing`。
- fatal `NETWORK_ERROR` 只调用一次 `startLoad()`；fatal `MEDIA_ERROR` 只调用一次 `recoverMediaError()`；重复失败或其它 fatal error 转为 `error` 并记录日志。
- `destroy()` 顺序为 `hls.destroy()` → `video.removeAttribute('src')` → `video.load()`，最后回到 `idle`。
- CommonJS 导出 `{ HlsPlayer }`，浏览器环境注册 `window.SyncPlayHlsPlayer`。

## §2 loadVideo m3u8 分支集成

`desktop/src/client/app.js` 已添加：

- `activeHls` 跟踪当前 HlsPlayer；每次加载先销毁旧 MSE 和旧 HLS，避免切换来源时泄漏。
- `\.m3u8(\?|$)` 检测，检测名称同时支持 URL 和本地 File 的文件名。
- m3u8 路由创建 `new SyncPlayHlsPlayer(video, src)`，等待 `attach()` 成功后保存为 `activeHls` 并返回。
- attach 失败时显示 `HLS 错误: ...` toast，并销毁已经创建的临时 player 后重新抛出错误。
- mp4 / webm / blob 默认路径和 B-C 容器路径保持不变。
- 未修改 `desktop/src/shared/sync-engine.js` 或 `desktop/src/shared/video-match.js`。
